## 🎯 每个阶段的角色 + 产出

| 阶段 | 主导角色 | 协作角色 | 产出 | skill |
|:--|:--|:--|:--|:--|
| ① 需求采集 | PM | 用户 / 业务方 | 需求一句话 + 范围边界 | brainstorming, clarification-checklist |
| ② 需求定义 | PM | 产品 lead | PRD.md + 验收标准 | prd-generation, reqdef-skill |
| ③ 需求拆解 | PM | dev / QA | WBS + 子任务 + Checklist | requirement-breakdown, planning-task-breakdown |
| ④ 交互设计 | 产品 lead | UX + dev lead | 原型 + UX 评审 | interaction-designer-skill, design |
| ⑤ 任务派发 | PM | 子角色 lead | TASK-ID + 5 件套 | agent-task-board, task-canvas-analysis |
| ⑥ 开发执行 | dev lead | dev1 / dev2 | 代码 + 单元测试 | code-review, claude-code-orchestrator |
| ⑦ 质量保障 | QA | dev | 测试报告 + 通过/打回 | diagnostician-skill, browser-testing-devtools |
| ⑧ demo 与上线 | PM + ops | dev | demo + 上线 | demo-generation, shipping-and-launch |
| ⑨ 文档沉淀 | doc | PM | ADR + 闭环报告 | documentation-adrs |

## 🚨 阶段间边界守

| 从 → 到 | 必带交付物 | 必停点 |
|:--|:--|:--|
| ① → ② | 需求一句话 + 范围边界 | 范围模糊必停 |
| ② → ③ | PRD + 验收标准 | PRD 不完整必停 |
| ③ → ⑤ | WBS + 子任务 + Checklist | WBS 缺验收必停 |
| ⑤ → ⑥ | TASK-ID + 5 件套 + lead | 派单越级必停 |
| ⑥ → ⑦ | 代码 + 单元测试 | 测试覆盖率 < 80% 必停 |
| ⑦ → ⑧ | 测试报告 + 通过 | QA 打回必重做 |
| ⑧ → ⑨ | demo + 上线报告 | 上线失败必回滚 |
| ⑨ → (下一个需求) | 闭环报告 + 教训 | 缺教训必补 |

## 📊 全流程健康度指标

| 指标 | 目标 | 测量频率 |
|:--|:--|:--|
| 需求到 PRD 平均时间 | < 2 天 | 每周 |
| PRD 到派工平均时间 | < 1 天 | 每周 |
| 派工到 done 平均时间 | < 5 天 | 每周 |
| 一次验收通过率 | > 80% | 每周 |
| 反思≠实证次数 | = 0 | 每日 |
| 边界守违例次数 | = 0 | 每日 |
