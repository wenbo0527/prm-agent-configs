# docs/多agent协作模型.md

> **作用**：定义多 agent 团队的协作规则、升级路径、决策机制

---

## 🏛️ 协作模型核心

### 三大原则

1. **PM 自治派工**：PM 在子角色范围内有派工权
2. **边界守**：每角色有清晰的能做 / 不能做
3. **升级路径清晰**：阻塞 / 决策冲突有明确升级路径

## 👥 典型 5 人阵型

```
┌──────────────────────────────────────────────┐
│                  PM (产品经理)                 │
│         派工 + 跟踪 + 验收 + 升级              │
└──────────────┬───────────────────────────────┘
               │
       ┌───────┼───────┬─────────┬─────────┐
       ▼       ▼       ▼         ▼         ▼
    产品 lead  dev lead  QA    doc    UX (可选)
       │       │       │       │       │
       ▼       ▼       ▼       ▼       ▼
    dev1/2   dev3/4  QA1/2  doc1
```

### 各角色核心职责

| 角色 | 核心职责 | 不做什么 |
|:--|:--|:--|
| **PM** | 派工 + 跟踪 + 验收 + 升级 | 不写代码 / 不直接派给执行者 |
| **产品 lead** | PRD + 需求拆解 + 验收业务 | 不写代码 / 不派工给 dev |
| **dev lead** | 拆任务给 dev + 代码评审 + 技术决策 | 不直接接 PM 任务（应通过产品 lead） |
| **QA** | 测试设计 + 独立验收 + 质量报告 | 不写生产代码 / 不直接上线 |
| **doc** | 文档沉淀 + ADR + 闭环报告 | 不决策业务 / 不验收代码 |

## 🚨 升级路径

| 场景 | 升级路径 |
|:--|:--|
| **PM ↔ 子角色冲突** | PM + 子角色 lead 协商 → 升级 CTO/上级 |
| **PM ↔ 用户冲突** | PM 提出 A/B/C → 用户拍板 |
| **子角色内部冲突** | 子角色 lead 仲裁 → 升级 PM |
| **阻塞 > 24h** | 戳破 → 升级 PM |
| **跨项目冲突** | PM 升级 CTO → 跨项目 PM 协商 |
| **反思≠实证严重违例** | 立即停手 + 升级 + 写教训 |

## 🔄 决策机制

### 决策类型

| 类型 | 决策者 | 时机 |
|:--|:--|:--|
| **战术决策**（任务级）| 子角色 lead | 实施前 |
| **产品决策**（功能级）| PM + 产品 lead | 派工前 |
| **架构决策**（技术级）| dev lead + PM | 实施前 |
| **战略决策**（项目级）| CTO/上级 | 重大节点 |
| **跨项目决策** | CTO + 跨 PM | 跨项目节点 |

### 决策点必停

任何决策前必输出 A/B/C 选项 + 推荐（详见 [反冗长 3 段式汇报](../lessons/反冗长-3段式汇报.md)）。

## 📋 协作 Checklist

### PM 每日

- [ ] 派单都有 TASK-ID + 5 件套？
- [ ] in_progress 任务都 24h 有进展？
- [ ] 阻塞任务都升级？
- [ ] 今日反思≠实证 = 0？
- [ ] 今日边界守违例 = 0？

### 子角色 lead 每日

- [ ] 收到的派单都 5min ack？
- [ ] 拆给执行者的任务都 update + get 实证？
- [ ] 24h 戳破 in_progress 任务？
- [ ] 今日反思≠实证 = 0？
- [ ] 今日边界守违例 = 0？

### 执行者（dev/QA/doc）每日

- [ ] 收到任务都 5min ack？
- [ ] 完成任务都带 grep 行号实证？
- [ ] 报告都 3 段式？
- [ ] 今日反思≠实证 = 0？
- [ ] 今日边界守违例 = 0？

## 🩸 协作常见冲突

### 冲突 1：PM 派单越级

```
症状：PM 直接派给 dev1
修复：派给 dev lead，让 lead 拆给 dev1
```

### 冲突 2：dev 自验收

```
症状：dev 写完代码自己说"通过"
修复：派给 QA，由 QA 独立验收
```

### 冲突 3：QA 直接上线

```
症状：QA 验收通过后自己部署
修复：派给 ops，由 ops 部署
```

### 冲突 4：PM close 别人任务

```
症状：A 派的任务，B close 了
修复：B 通知 A，由 A close
```
