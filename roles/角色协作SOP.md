# 角色协作 SOP · 通用协作规则（v1.0）

> **作用**：定义多 agent 团队通用协作规则，适用于 5 / 3 / 1 人阵型
> **核心**：派工 + 跟踪 + 验收 + 升级 + 反思

---

## 🎯 4 大协作硬规则

### 规则 1：派给角色，不派给人

PM 派工 = 派给子角色（产品 lead / dev lead / QA / doc），不直接派给执行者。

```
✅ PM → dev lead → dev1
❌ PM → dev1（越级）
```

### 规则 2：update 后必 get 二次实证

任何 task_tool update / 文件 write / 代码修改后，必立即 get 验证。

```bash
task_tool.py update --id TASK-X --assignee dev
task_tool.py get --id TASK-X  # 必跑
```

### 规则 3：5min 内必 ack

收到派单 / 任务 / 通知 → 5min 内必回复，不沉默不阻塞。

### 规则 4：反思≠实证 = 0

任何"已完成 / 已修复 / 已派"必带 grep / cat / stat 实证。

## 📋 派工 5 件套

| 字段 | 必填 | 示例 |
|:--|::|:--|
| TASK-ID | ✅ | TASK-20260813-001 |
| 子角色 | ✅ | dev / QA / 产品 / doc |
| 任务标题 | ✅ | "实现 XX 功能" |
| 验收标准 | ✅ | "用户能 XX 操作，测试用例 3/3 通过" |
| 截止时间 | ✅ | 2026-08-15 18:00 |

## 📊 跟踪 SOP

| 时机 | 动作 |
|:--|:--|
| **每日** | 看 in_progress 任务 ≥ 1 次 |
| **24h 未推进** | 戳破（提醒相关人） |
| **48h 阻塞** | 升级 PM → CTO |
| **任务完成** | 验收 + 闭环 |
| **任务打回** | 通知 + 重派 |

## ✅ 验收 SOP

### cross-check ≥ 2 维度

| 任务类型 | 维度 1 | 维度 2 |
|:--|:--|:--|
| **代码** | 功能（手动跑）| 代码（review）|
| **UI** | 设计（截图比对）| 功能（点击跑通）|
| **文档** | 内容（read 全文）| 格式（lint）|
| **数据** | 业务（query）| 性能（explain plan）|

### 验收 Checklist（通用）

- [ ] 功能正常（按需求走一遍）
- [ ] 边界 case 处理（异常输入 / 错误码）
- [ ] 代码质量（如有代码）：无 lint 错误 + 测试覆盖率 > 80%
- [ ] 文档完整（如有文档）：API doc + 用户指南
- [ ] 反思≠实证 = 0

## 🚨 升级 SOP

| 场景 | 升级路径 |
|:--|:--|
| **PM ↔ 子角色冲突** | 协商 → 升级 CTO |
| **子角色内部冲突** | 子角色 lead 仲裁 → 升级 PM |
| **阻塞 > 24h** | 戳破 → 升级 PM |
| **跨项目冲突** | PM 升级 CTO → 跨 PM 协商 |
| **反思≠实证严重违例** | 立即停手 + 升级 + 写教训 |

## 🩸 协作常见错误

### 错误 1：派单越级

```
症状：PM 直接派给 dev1
修复：派给 dev lead
```

### 错误 2：声明≠落地

```
症状：口头说"已派"但 task_tool 没 update
修复：update + get 二次实证
```

### 错误 3：派单后失联

```
症状：派出去 1 周没跟踪
修复：每日看 in_progress
```

### 错误 4：验收单维度

```
症状：PM 只看 demo 截图
修复：cross-check ≥ 2 维度
```

### 错误 5：close 别人任务

```
症状：PM close 别人派的任务
修复：通知派单者，由他 close
```

## 📊 协作健康度自检（每周）

- [ ] 派单都带验收标准？

- [ ] in_progress 任务都 24h 有进展？
- [ ] 已派任务的 close 都带闭环文档？
- [ ] 5min ack 率 100%？
- [ ] 反思≠实证次数 = 0？
- [ ] 边界守违例次数 = 0？
