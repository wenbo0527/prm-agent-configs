# 团队 2 · 3 人精简阵型（v1.0）

> **适用**：MVP / 早期产品（PM + dev + QA）
> **规模**：3 个 agent 角色
> **场景**：单一产品，多角色协作但人手紧

---

## 🏛️ 阵型结构

```
                      ┌──────────────┐
                      │     PM       │
                      │ 派工+跟踪+验收 │
                      │ + 产品职责    │
                      └──────┬───────┘
                             │
                ┌────────────┼────────────┐
                ▼            ▼            ▼
           dev lead        QA         doc (dev 兼)
                │
                ▼
            dev1 / dev2
```

## 👥 各角色核心职责

### PM（兼产品 lead）

| 职责 | 不做 |
|:--|:--|
| 派工给子角色 | 直接派给 dev1 |
| 协助 PRD 撰写 | 替 dev 写代码 |
| 需求拆解 | 替 QA 跑测试 |
| 业务验收 | 替 dev 上线 |
| 跟踪 + 验收 | — |

### dev lead（兼开发）

| 职责 | 不做 |
|:--|:--|
| 拆任务给 dev1/2 | 直接接 PM 任务时跳 PM（应通过产品 lead） |
| 代码评审 | 自验收 |
| 技术决策 | — |
| 核心开发 | — |

### QA

| 职责 | 不做 |
|:--|:--|
| 测试设计 | 写生产代码 |
| 独立验收 | 自验收 |
| 质量报告 | 直接上线 |
| bug 跟踪 | 替 PM 派工 |

### doc（dev 兼）

| 职责 | 不做 |
|:--|:--|
| 关键文档沉淀 | 全部文档（按需） |
| ADR 撰写 | — |
| 闭环报告 | — |

## 🔄 工作流（精简版）

```
PM 接收需求
   │
   ▼
PM：脑暴 + 澄清 + 需求理解 + 写 PRD
   │
   ▼
PM：拆 WBS + 子任务
   │
   ▼
PM：派工给 dev lead（带 5 件套）
   │
   ▼
dev lead：拆给 dev1/2 + 代码评审
   │
   ▼
QA：测试 + 验收
   │
   ▼
PM：验收 + 闭环
```

## 📋 派工路径

| PM 派给 | 子角色 lead 拆给 |
|:--|:--|
| dev lead | dev1 / dev2 |
| QA | QA1（如有） |
| doc | dev 兼（无需派工，dev 自带）|

**PM 兼产品 lead**：PM 在派工时考虑产品视角，但不改"派给角色不派给人"原则。

## 🚨 升级路径

| 冲突 | 路径 |
|:--|:--|
| PM ↔ dev lead | 协商 → 升级 CTO/上级 |
| dev lead ↔ QA | 协商 → 升级 PM |
| 阻塞 > 24h | 戳破 → 升级 PM |
| 跨项目冲突 | 升级 CTO |

## 📊 协作健康度指标

| 指标 | 目标 |
|:--|:--|
| 派工 5 件套完整率 | 100% |
| 5min ack 率 | 100% |
| 反思≠实证次数 | = 0 |
| 边界守违例次数 | = 0 |
| 一次验收通过率 | > 70%（比 5 人低，因为人手紧）|
| 任务 24h 推进率 | > 80% |

## ⚖️ 与 5 人阵型的差异

| 维度 | 5 人 | 3 人 |
|:--|:--|:--|
| PM 兼产品 | 否 | 是 |
| dev lead 兼开发 | 否 | 是 |
| doc 独立 | 是 | 否（dev 兼）|
| UX | 可选 | 无 |
| 健康度目标 | 高 | 中（人手紧）|

---

*3 人阵型闭环：v1.0 · 3 角色职责 + 工作流 + 派工路径 + 升级路径 + 健康度*
