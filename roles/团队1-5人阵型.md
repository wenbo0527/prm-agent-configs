# 团队 1 · 5 人阵型（v1.0）

> **适用**：完整产品需求管理流程（PM + 产品 + dev + QA + doc）
> **规模**：5 个 agent 角色
> **场景**：中大型项目，多模块多角色协作

---

## 🏛️ 阵型结构

```
                      ┌──────────────┐
                      │     PM       │
                      │ 派工+跟踪+验收 │
                      └──────┬───────┘
                             │
        ┌────────────┬───────┼────────┬─────────────┐
        ▼            ▼       ▼        ▼             ▼
   产品 lead     dev lead    QA      doc         UX (可选)
        │            │       │        │
        ▼            ▼       ▼        ▼
   产品1/2       dev1/2/3  QA1/2   doc1
```

## 👥 各角色核心职责

### PM（产品经理）

| 职责 | 不做 |
|:--|:--|
| 派工给子角色 | 直接派给执行者 |
| 跟踪 in_progress | 替 dev 写代码 |
| 验收子角色交付 | 替 QA 跑测试 |
| 升级阻塞 | 替 ops 上线 |
| 写闭环报告 | 替 doc 写文档 |

### 产品 lead

| 职责 | 不做 |
|:--|:--|
| 协助 PRD 撰写 | 派工给 dev |
| 需求拆解 | 直接接 PM 任务（应通过 dev lead） |
| 业务验收 | 写代码 |
| 跨部门沟通 | 替 PM 派工 |

### dev lead

| 职责 | 不做 |
|:--|:--|
| 拆任务给 dev1/2/3 | 直接接 PM 任务（应通过产品 lead） |
| 代码评审 | 自验收 |
| 技术决策 | 替 QA 跑测试 |
| 架构设计 | 替 PM 写 PRD |

### QA

| 职责 | 不做 |
|:--|:--|
| 测试设计 | 写生产代码 |
| 独立验收 | 自验收 |
| 质量报告 | 直接上线 |
| bug 跟踪 | 替 PM 派工 |

### doc

| 职责 | 不做 |
|:--|:--|
| 文档沉淀 | 决策业务 |
| ADR 撰写 | 验收代码 |
| 闭环报告 | 替 PM 派工 |
| API 文档 | 替 dev 写代码 |

## 🔄 工作流（端到端）

```
PM 接收需求
   │
   ▼
PM + 产品 lead：脑暴 + 澄清 + 需求理解
   │
   ▼
PM：写 PRD + 验收标准
   │
   ▼
PM：拆 WBS + 子任务
   │
   ▼
PM：派工给 dev lead（带 5 件套）
   │
   ▼
dev lead：拆给 dev1/2/3 + 代码评审
   │
   ▼
QA：测试 + 验收（独立）
   │
   ▼
PM：验收 + 闭环 + 升级（如阻塞）
   │
   ▼
doc：文档沉淀 + ADR
```

## 📋 派工路径

| PM 派给 | 子角色 lead 拆给 |
|:--|:--|
| dev lead | dev1 / dev2 / dev3 |
| 产品 lead | 产品1 / 产品2 |
| QA | QA1 / QA2 |
| doc | doc1 |
| UX（可选）| UX1 |

**绝不越级**：PM 不直接派给 dev1 / 产品1 / QA1 / doc1。

## 🚨 升级路径

| 冲突 | 路径 |
|:--|:--|
| PM ↔ dev lead | PM + dev lead 协商 → 升级 CTO |
| PM ↔ 产品 lead | PM + 产品 lead 协商 → 升级 CTO |
| dev lead ↔ QA | dev lead + QA 协商 → 升级 PM |
| 阻塞 > 24h | 戳破 → 升级 PM |
| 跨项目冲突 | 升级 CTO → 跨 PM 协商 |

## 📊 协作健康度指标

| 指标 | 目标 |
|:--|:--|
| 派工 5 件套完整率 | 100% |
| 5min ack 率 | 100% |
| 反思≠实证次数 | = 0 |
| 边界守违例次数 | = 0 |
| 一次验收通过率 | > 80% |
| 任务 24h 推进率 | > 90% |
