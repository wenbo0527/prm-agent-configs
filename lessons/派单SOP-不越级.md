# 派单SOP-不越级 · PM 派工硬规则范式（v1.0）

> **核心问题**：PM 派工越级（派给人而非角色）+ 行动≠落地（声明≠实际）
> **锁版守**：派给角色不派给人 + update 必 get 二次实证

---

## 🎯 范式定义

PM 派工 = 把任务分给**子角色**（产品 / dev / QA / doc），而非具体执行者（dev1 / dev2）。

## ✅ 正确范式

```
PM（派工）→ 子角色 lead（拆任务给执行者）→ 执行者（完成任务）
```

**关键**：
- PM 不直接派给执行者
- 子角色 lead 有派工自主权
- PM 只验收子角色交付的结果

## ❌ 反范式（违例）

```
❌ PM → dev1（越级）
❌ PM → dev2（越级）
❌ PM 自己改代码（越权）
```

## 🩸 4 类常见错误

### 错误 1：派单越级
- **现象**：PM 直接派给 dev1
- **后果**：dev lead 失去派工权 + 团队层级混乱 + 反思≠实证
- **修复**：派给 dev lead，让他拆给 dev1

### 错误 2：派单缺验收
- **现象**：只派"实现 XX"，没说怎么算完成
- **后果**：dev 完成后 PM 主观判定，引发争议
- **修复**：派单必带验收 Checklist（功能 + 代码 + 边界 case）

### 错误 3：声明≠落地
- **现象**：口头/飞书说"已派"，但 task_tool 没 update
- **后果**：任务板失真 + 团队看不到真实状态 + 反思≠实证
- **修复**：update 后立即 get 二次实证

### 错误 4：派单后失联
- **现象**：派出去 1 周没跟踪
- **后果**：任务漂移 / 阻塞无人知
- **修复**：每日 ≥1 次看 in_progress，24h 未推进 → 戳破

## 🛠️ 派工 5 件套（必填）

| 字段 | 必填 | 示例 |
|:--|::|:--|
| **TASK-ID** | ✅ | TASK-20260813-001 |
| **子角色** | ✅ | dev / QA / 产品 / doc |
| **任务标题** | ✅ | "实现 XX 功能" |
| **验收标准** | ✅ | "用户能 XX 操作，测试用例 3/3 通过" |
| **截止时间** | ✅ | 2026-08-15 18:00 |

## 🚨 5min ack 规则（反沉默）

收到派单 → 5min 内必须回复：
- ✅ "收到，已派给 dev lead，预计 X 完成"
- ❌ 沉默 1 小时（让上游以为你没收到）

## 📋 派工后必做

| 时机 | 动作 |
|:--|:--|
| 派工后 | update + get 二次实证 |
| 每 24h | 检查 in_progress 任务进度 |
| 任务完成 | 验收（cross-check ≥ 2 维度）|
| 任务阻塞 | 戳破 / 升级 |
| 任务闭环 | 写闭环文档 + 更新 MEMORY |

## 📊 派工健康度自检

- [ ] 本周派单都有 TASK-ID？
- [ ] 派单都带验收标准？
- [ ] 派单都 update 成功并 get 验证？
- [ ] in_progress 任务都 24h 有进展？
- [ ] 已派任务的 close 都带闭环文档？
