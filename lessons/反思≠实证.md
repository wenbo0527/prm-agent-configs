# 反思≠实证 · 范式（v1.0）

> **核心问题**：声明"已完成 / 已修复" ≠ 实际验证
> **锁版守**：报告必带"位置 + 风险 + 修复 + 验证"四件套

---

## 🎯 范式定义

**反思 = 思考"我做了什么"**
**实证 = 证明"它真的发生了"**

**反思≠实证** = 反思了但没实证 = 虚假完成

## ❌ 反范式（违例）

```
"我已经把 X 完成了。" → 反思，没实证
"我修复了 bug。" → 反思，没实证
"路径已落档。" → 反思，没实证
```

## ✅ 正范式

```
"X 已完成。位置：`src/X.ts:42`，风险：Y，修复：Z，验证：单元测试 3/3 通过 + 手动跑通。"
```

**四件套**：
1. **位置**：在哪（绝对路径 + 行号）
2. **风险**：可能什么问题
3. **修复**：怎么修的
4. **验证**：怎么证明修好了

## 🩸 4 类常见错误

### 错误 1：路径虚指
- **现象**：说"已落档到 `MEMORY.md`"但实际没改
- **后果**：反思≠实证
- **修复**：`ls -la + stat + cat 头 5 行` 验证

### 错误 2：完成度虚高
- **现象**：说"100% 完成"但实际还有边界 case
- **后果**：上线后 bug + 反思≠实证
- **修复**：列具体验收项 + cross-check

### 错误 3：声明"已派"
- **现象**：口头说"已派给 dev"，但 task_tool 没 update
- **后果**：任务板失真
- **修复**：update + get 二次实证

### 错误 4：报告模糊
- **现象**：报告"差不多完成了"
- **后果**：无法判断真伪
- **修复**：量化（百分比 / 行数 / 测试用例数）

## 🛠️ 实证工具

| 工具 | 用途 | 示例 |
|:--|:--|:--|
| `ls -la` | 验证路径存在 | `ls -la /path/to/file` |
| `stat` | 验证文件大小/mtime | `stat /path/to/file` |
| `cat` | 验证内容 | `cat /path/to/file \| head -5` |
| `find` | 验证存在性 | `find / -name "X"` |
| `grep -rn` | 验证引用 | `grep -rn "X" /path/` |
| `task_tool.py get` | 验证任务状态 | `task_tool.py get --id TASK-X` |
| `task_tool.py list` | 验证任务列表 | `task_tool.py list --filter` |

## 📋 报告模板

```markdown
## 完成报告

**任务**：[任务标题]
**TASK-ID**：[TASK-XXX]

### 四件套
- **位置**：`[绝对路径]:[行号]`
- **风险**：[可能问题]
- **修复**：[具体动作]
- **验证**：
  - [ ] 单元测试通过（数量）
  - [ ] 手动跑通
  - [ ] cross-check（≥ 2 维度）
```

## 📊 反思≠实证自检（每次报告前）

- [ ] 报告带具体路径/行号？
- [ ] 报告带 grep/stat 实证命令输出？
- [ ] 报告带验收 Checklist？
- [ ] 报告带 cross-check 结果？
- [ ] 报告没说"差不多 / 应该 / 我觉得"？
