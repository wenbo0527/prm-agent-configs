# 行动≠落地 · 范式（v1.0）

> **核心问题**：声明"已做 / 已改 / 已派" ≠ 实际生效
> **锁版守**：任何 update 必 `get` 二次实证

---

## 🎯 范式定义

**行动 = 发出指令（点按钮 / 发命令 / 写报告）**
**落地 = 实际生效（数据真改了 / 任务真更新了 / 代码真跑了）**

**行动≠落地** = 行动了但没落地 = 假装做事

## ❌ 反范式（违例）

```
"我已派给 dev" → 行动，没落地（task_tool 没 update）
"我已修改代码" → 行动，没落地（文件没真改）
"我已 close 任务" → 行动，没落地（task_tool 没 close）
```

## ✅ 正范式

```
"我已派给 dev。验证：task_tool get TASK-X 显示 assignee=dev, status=in_progress。"
"我已修改代码。验证：stat 显示文件 mtime=刚才 + cat 显示新内容。"
"我已 close 任务。验证：task_tool get TASK-X 显示 status=done。"
```

## 🩸 4 类常见错误

### 错误 1：声明"已派"
- **现象**：口头/飞书说"已派"，但 task_tool 没 update
- **后果**：任务板失真 + 团队看不到真实状态
- **修复**：update + get 二次实证

### 错误 2：声明"已修"
- **现象**：说"bug 已修"，但代码没真改
- **后果**：上线后 bug 还在
- **修复**：`git diff` + `stat` mtime 验证

### 错误 3：声明"已 close"
- **现象**：说"任务已 close"，但 task_tool 没 close
- **后果**：任务板显示 in_progress 实际已完
- **修复**：close + get 二次实证

### 错误 4：声明"已落档"
- **现象**：说"已写到 MEMORY.md"，但文件没真改
- **后果**：反思≠实证
- **修复**：`stat` + `cat` 验证

## 🛠️ 二次实证 SOP（任何 update 后）

```bash
# 步骤 1：update
task_tool.py update --id TASK-X --assignee dev --status in_progress

# 步骤 2：立即 get 验证（hard rule）
task_tool.py get --id TASK-X

# 步骤 3：cat 实际值
echo "assignee 实际值 = $(task_tool.py get --id TASK-X --field assignee)"
```

## 📋 不同 update 的实证工具

| update 类型 | 实证工具 |
|:--|:--|
| 任务 update | `task_tool.py get` |
| 文件 write | `stat` mtime + `cat` 头 5 行 |
| 代码修改 | `git diff` + 测试通过 |
| 配置修改 | 重启服务 + curl 测试 |
| 数据库修改 | `SELECT` 验证 |
| 部署 | curl 健康检查 + 日志查看 |

## 🛡️ 5min 内必 ack（不沉默）

发出 update → 5min 内必 get 验证：
- ✅ "已派，验证通过"
- ❌ 发出 update 但不验证（10min 后才发现 update 失败）
