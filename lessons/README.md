# lessons/ · PM 协作教训（v1.0）

> **聚焦**：PM 角色协作中常见踩坑的范式沉淀
> **原则**：脱敏（无真实姓名/IP/项目代号）+ 范式级（可复用）
> **使用**：每个 PM agent 启动时必读，决策点扫描前必查

## 🩸 7 大范式（必读）

| 范式 | 文件 | 核心问题 | 锁版守 |
|:--|:--|:--|:--|
| **派单不越级** | [派单SOP-不越级.md](派单SOP-不越级.md) | PM 派工越级 / 行动≠落地 | 派给角色不派给人 + update 必 get 实证 |

## 📚 何时读哪个

| 场景 | 必读 |
|:--|:--|
| 派工前 | 派单SOP-不越级 + 边界守 |
| 写"已完成"报告前 | 反思≠实证 + 行动≠落地 |
| 升级 / 阻塞 / 冲突 | 边界守 + 反糊弄 |
| 复杂 bug / 任务 | 治本原则 5 步法 |
| 任何汇报 | 反冗长 3 段式 |
| 启动流程 | 全部（按需加载） |

## 🎯 范式 vs 教训的关系

- **范式**：可复用的模式（"PM 派工给角色不派人"）
- **教训**：具体场景的踩坑实例（"某次 PM 直接派给 dev1 导致反思≠实证"）

本仓**只沉淀范式**，具体教训请各团队内部记录（避免暴露内部信息）。

## 🛡️ 锁版守

每个范式都有"锁版守"——即该范式的硬规则。锁版守 = 不可破坏的硬规则。

违反锁版守 = 触发反思≠实证，需立即 v15-2.0 升级版硬约束。
