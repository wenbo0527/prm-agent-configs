# planning-task-breakdown SOP · 任务规划（WBS）（v1.1）

> **阶段**：03 需求拆解
> **目标**：把需求拆解转成可派单的任务清单

---

## 🎯 触发条件

- ✅ 需求拆解已完成
- ✅ 即将派工到角色
- ✅ 需要决定里程碑 / Sprint 划分

## 🛠️ 操作步骤（5 步）

### 第 1 步：选定 Sprint 节奏

| 节奏 | 适用 |
|:--|:--|
| **1 周 Sprint** | 紧急项目 / MVP |
| **2 周 Sprint** | 标准（Scrum 推荐）|
| **3 周 Sprint** | 慢节奏 / 大型项目 |
| **月 Sprint** | 长期规划 |

### 第 2 步：决定每个 Sprint 容量

```
Sprint 容量 = 团队总人天 × 0.7（扣减 buffer）
例：3 人 × 10 天 × 0.7 = 21 人天 / Sprint
```

### 第 3 步：分配子任务到 Sprint

```markdown
## Sprint 1（YYYY-MM-DD ~ YYYY-MM-DD）
| ID | 标题 | 角色 | 工时 |
|:--|:--|:--|:--|
| ST1.1 | [动作] | dev | 2d |
| ST1.2 | [动作] | dev | 1d |
| ST1.3 | [动作] | QA | 1d |

## Sprint 2
...
```

### 第 4 步：识别关键路径

```
关键路径 = 决定项目最短工期的子任务序列

非关键路径任务可作为 buffer
```

### 第 5 步：风险预演

```
Sprint 计划：
- 必达成：P0 任务（X 个）
- 应达成：P1 任务（Y 个）
- 可达成：P2 任务（Z 个）

风险：
- 人力风险：[角色] 离场 → 应对：交叉培训
- 技术风险：[难点] → 应对：提前 PoC
- 依赖风险：[外部依赖] → 应对：备选方案
```

## ✅ 验收 Checklist

- [ ] Sprint 节奏明确？
- [ ] 容量按 0.7 buffer 扣减？
- [ ] 每个 Sprint 任务清单 + 工时？
- [ ] 关键路径标注？
- [ ] 风险预演 ≥ 3 个？

## 🩸 反范式

- **Sprint 容量满负荷**（无 buffer）→ 任何意外都崩
- **P0 没识别** → Sprint 做完了但核心没做
- **关键路径漏标** → 误判项目完成时间
