# claude-code-orchestrator SOP · CC 编排（v1.1）

> **阶段**：06 开发执行
> **目标**：用 Claude Code (CC) 子代理并行执行开发

---

## 🎯 触发条件

- ✅ 多步并行任务（如部署 5 个 子应用）
- ✅ 技术决策（需要快速调研）
- ✅ 短任务（< 2 分钟）

## 🛠️ 操作步骤（5 步）

### 第 1 步：判断是否需要 CC

```
决策树：
- 任务 < 2 分钟 → 钟离直接做
- 多步并行（≥ 3 个独立任务）→ CC 执行
- 技术决策（架构选型）→ 钟离直接做
- 长任务（> 30 分钟）→ PM 派单，不用 CC
```

### 第 2 步：拆分任务

```
CC 任务粒度：
- 每个子任务独立可完成
- 每个子任务 < 5 分钟
- 子任务间无依赖（或弱依赖）

反范式：
- 1 个 CC 任务 1 小时 → 拆分
- 强依赖子任务串行 → 合并
```

### 第 3 步：派单到 CC

```
每个 CC 子任务：
- 明确输入（前置任务输出）
- 明确输出（产出文件 / 状态）
- 验证标准（怎么算"做对了"）

例：
派给 CC 1：实现用户注册接口
- 输入：API 文档 + 数据库 schema
- 输出：user/register.ts + 单元测试
- 验证：3 个测试用例通过 + curl 200
```

### 第 4 步：CC 执行 + 监控

```
- 给每个 CC 子任务独立 session
- 钟离 / PM 监督进度
- 任子任务失败 → 立即诊断 + 重试或换 agent
```

### 第 5 步：集成 + 验收

```
- 收集所有 CC 子任务输出
- 集成（处理依赖）
- 验收（cross-check ≥ 2 维度）
- 闭环（写文档 + 更新任务板）
```

## ✅ 验收 Checklist

- [ ] 决策树判断"该不该用 CC"？
- [ ] 子任务粒度 < 5min？
- [ ] 每个子任务有输入/输出/验证？
- [ ] 失败有应急？
- [ ] 集成 + 验收完整？

## 🩸 反范式

- **小任务用 CC**（< 2min）→ 浪费
- **大任务用 CC**（> 30min）→ 失控
- **强依赖子任务并行** → 互相阻塞
- **没验证就集成** → bug 进生产
