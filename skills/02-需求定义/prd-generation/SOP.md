# prd-generation SOP · PRD 生成（v1.1）

> **阶段**：02 需求定义
> **目标**：把需求理解变成可执行的 PRD

---

## 🎯 触发条件

- ✅ 需求理解已完成
- ✅ 用户故事 ≥ 5 个
- ✅ 需要立项 / 启动开发
- ✅ 跨团队需要参考文档

## 🛠️ 操作步骤（5 步）

### 第 1 步：PRD 模板（用公司标准）

**标准 PRD 模板**：

```markdown
# PRD v1.0 · [产品名称]

## 1. 背景与目标
- 背景：[为什么做]
- 目标：[达成什么]
- 关键指标：[怎么算成功]

## 2. 用户与场景
- 目标用户：[谁]
- 核心场景：[用在哪]

## 3. 用户故事
[从需求理解文档导入]

## 4. 功能需求
- F1：[功能 1]
- F2：[功能 2]
...

## 5. 非功能需求
[NFR 列表]

## 6. 风险与缓解
[风险表]

## 7. 里程碑
- M1：[时间 + 交付]
- M2：[时间 + 交付]

## 8. 附录
- 术语表
- 参考文档
```

### 第 2 步：拆功能到最小可交付

```
每个功能拆到：
- 1 个 dev 能在 1-3 天内完成
- 有明确验收标准
- 有 mockup / 流程图
```

**反范式**：1 个功能跨 2 周 → 拆分

### 第 3 步：优先级排序

| 优先级 | 标准 | 例子 |
|:--|:--|:--|
| **P0** | MVP 必做 | 核心流程 |
| **P1** | MVP 后必做 | 体验优化 |
| **P2** | 可选 | 锦上添花 |
| **P3** | 未来 | v2.0+ |

**反范式**：P0 太多 → MVP 不 MVP

### 第 4 步：里程碑 + 排期

```
M1 (T+1 周): P0 全做完
M2 (T+2 周): P1 全做完
M3 (T+3 周): P2 部分做 + 内测
M4 (T+4 周): 上线
```

**反范式**：排期太乐观 → 实际拖 2 倍

### 第 5 步：PRD Review

```
必 review 的角色：
- 产品 lead（业务准确性）
- 技术 lead（技术可行性）
- 设计 lead（UX 一致性）
- QA lead（验收标准完整性）
- 上级（资源 / 优先级）

review 输出：comment → 修改 → 通过 → 锁定 v1.0
```

## ✅ 验收 Checklist

- [ ] 8 个章节齐全？
- [ ] 用户故事 ≥ 5？
- [ ] 功能拆到 1-3 天可完成？
- [ ] 优先级排序（MVP 突出）？
- [ ] 里程碑 + 排期合理？
- [ ] ≥ 3 个角色 review 通过？

## 🩸 反范式

- **PRD = 大杂烩**：8 章不全，缺验收标准 → 反思≠实证
- **PRD 不锁版**：v0.1 / v0.2 / v0.3 一直改 → dev 混乱
- **PRD = 文档摆设**：写完不 review → 团队没用
