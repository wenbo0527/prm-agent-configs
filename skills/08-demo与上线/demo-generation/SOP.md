# demo-generation SOP · Demo 生成（v1.1）

> **阶段**：08 demo 与上线
> **目标**：快速产出可演示的 demo

---

## 🎯 触发条件

- ✅ 早期产品需要快速验证
- ✅ 投资人 / 客户 demo
- ✅ 内部汇报

## 🛠️ 操作步骤（5 步）

### 第 1 步：定义 demo 目标

```
明确：
- 受众：[投资人 / 客户 / 内部]
- 时长：[5min / 30min / 1h]
- 重点：[核心流程 / 差异化 / ROI]
```

### 第 2 步：选 demo 类型

| 类型 | 适用 |
|:--|:--|
| **录屏** | 简单 / 1-3 流程 |
| **截图** | 静态展示 |
| **交互原型** | Figma / Axure |
| **真实部署** | 最强但最贵 |
| **AI 自动 Demo** | 诊断器类工具 |

### 第 3 步：准备 demo 环境

```
- [ ] 数据 mock（不要空数据）
- [ ] 测试账号
- [ ] 备份方案（demo 失败的应急）
- [ ] 网络稳定（提前测）
```

### 第 4 步：脚本 + 时长控制

```
脚本模板：

## 开场（30s）
- 一句话价值主张

## 核心演示（3min）
- 场景 1：[用户痛点] → [我们的方案]
- 场景 2：[数据 / 效果对比]
- 场景 3：[独特能力]

## 收尾（30s）
- 下一步 CTA
```

### 第 5 步：复盘 + 优化

```
demo 后立即：
- 听众反馈记录
- 卡顿 / 问题清单
- 下次优化清单

归档：
- demo 视频
- 反馈记录
- 数据指标
```

## ✅ 验收 Checklist

- [ ] 目标清晰（受众 / 时长 / 重点）？
- [ ] demo 类型匹配目标？
- [ ] 数据 mock 真实？
- [ ] 脚本 + 时长控制？
- [ ] demo 后复盘？

## 🩸 反范式

- **demo = 真实系统**（没准备）→ 翻车
- **demo 跑偏**（没脚本）→ 没突出价值
- **不复盘** → 每次都翻同样的车
