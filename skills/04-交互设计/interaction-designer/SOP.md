# interaction-designer SOP · 交互设计（v1.1）

> **阶段**：04 交互设计
> **目标**：把需求转成可用 / 易用的交互方案

---

## 🎯 触发条件

- ✅ WBS 已锁定
- ✅ 即将进入开发
- ✅ 需要 UX 评审
- ✅ 涉及多端（Web / 小程序 / App）

## 🛠️ 操作步骤（5 步）

### 第 1 步：信息架构

```
页面层级：
- 一级：[首页 / 我的]
- 二级：[列表 / 详情]
- 三级：[表单 / 弹窗]

反范式：层级过深（>5 层）→ 用户迷失
```

### 第 2 步：用户旅程

```
用户在产品中的关键路径：
1. 进入 → 看到什么？
2. 操作 → 做什么？
3. 完成 → 得到什么？

每步标注情绪（兴奋 / 中性 / 困惑 / 挫败）
```

### 第 3 步：交互流程图

```
用 Mermaid / Whimsical / Figma 画：
- 主流程（happy path）
- 异常流程（错误 / 边界）
- 权限流程（不同角色看到的不同）
```

### 第 4 步：原型 + 评审

| 原型级别 | 工具 | 适用 |
|:--|:--|:--|
| **草图** | 纸笔 / Excalidraw | 内部对齐 |
| **低保真** | Figma / Axure | UX 评审 |
| **高保真** | Figma / Sketch | 用户测试 |

**反范式**：没评审就开发 → 改 3 遍

### 第 5 步：设计交付

交付物清单：
```markdown
## 设计交付物 v1.0
- [ ] 信息架构图
- [ ] 用户旅程图
- [ ] 主流程图（Mermaid / Figma）
- [ ] 异常流程图
- [ ] 原型（Figma 链接）
- [ ] 设计规范（颜色 / 字体 / 间距）
- [ ] 组件库（如用 Arco Design / Ant Design）
```

## ✅ 验收 Checklist

- [ ] 信息架构图清晰？
- [ ] 用户旅程覆盖核心场景？
- [ ] 主流程 + 异常流程图完整？
- [ ] 原型 ≥ 1 轮 UX 评审？
- [ ] 设计交付物 7 件套齐全？

## 🩸 反范式

- **跳过用户旅程** → 漏掉关键情绪点
- **原型没评审** → 改 3 遍
- **设计规范缺失** → 视觉不一致
- **多端不统一** → 用户体验割裂
