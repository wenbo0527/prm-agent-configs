# diagnostician SOP · AI 诊断器（v1.1）

> **阶段**：07 质量保障
> **目标**：用 AI 辅助业务 / 技术诊断

---

## 🎯 触发条件

- ✅ 模糊需求需要结构化
- ✅ 复杂问题需要多维分析
- ✅ 需要"第二步意见"

## 🛠️ 操作步骤（5 步）

### 第 1 步：准备输入

```
输入清单：
- [ ] 问题描述（背景 + 当前状态）
- [ ] 已尝试的方案 + 结果
- [ ] 关键约束（时间 / 成本 / 资源）
- [ ] 期望输出（方案 / 评估 / 决策）
```

### 第 2 步：选诊断模式

| 模式 | 适用 |
|:--|:--|
| **5 步追问** | 模糊需求澄清 |
| **5 维评分** | 方案对比 |
| **自动 Demo** | 快速验证 |
| **架构评估** | 技术选型 |
| **风险扫描** | 上线前 |

### 第 3 步：执行诊断

```
AI 输出结构：
1. 现状分析（事实）
2. 关键问题（不超过 3 个）
3. 候选方案（2-3 个 A/B/C）
4. 推荐方案 + 理由
5. 风险与缓解
```

### 第 4 步：人工验证

```
AI 输出 ≠ 真理
必做：
- [ ] 关键事实 cross-check（用真实数据验证）
- [ ] 推荐方案问"为什么"（AI 解释）
- [ ] 边界 case 列举
```

### 第 5 步：决策 + 闭环

```
决策：
- 采纳 AI 推荐 → 写决策记录
- 不采纳 → 标注原因
- 部分采纳 → 标注采纳部分

闭环：
- 决策后 24h 复检
- 验证 AI 推荐是否真有效
- 写教训（如有偏差）
```

## ✅ 验收 Checklist

- [ ] 输入清单 4 件齐全？
- [ ] 选对诊断模式？
- [ ] AI 输出 5 部分结构？
- [ ] 关键事实 cross-check？
- [ ] 决策有记录？

## 🩸 反范式

- **AI 输出 = 真理** → 决策偏差
- **没输入清单** → AI 输出无针对性
- **不复检** → AI 错也不知道
