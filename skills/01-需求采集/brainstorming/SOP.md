# brainstorming SOP · 需求脑暴（v1.1）

> **阶段**：01 需求采集
> **目标**：把模糊需求变成清晰范围

---

## 🎯 触发条件

**满足以下任一**：

- ✅ 用户提出"我想做 XX"（模糊需求）
- ✅ 多方对需求理解不一致
- ✅ 新项目从 0 到 1 起步
- ✅ 需求变更需要重新对齐

## 🛠️ 操作步骤（5 步）

### 第 1 步：界定脑暴范围（5min）

```
✅ "我们今天脑暴的是 XX，目标是 YY"
✅ 范围边界：在 [边界内] 做 [动作]，不在 [边界外] 做
```

**反范式**：范围太大（如"做个像淘宝的电商"）→ 拆小

### 第 2 步：邀请角色（3min）

```
必邀请：
- 用户 / 业务方（需求发起方）
- 产品 lead（懂业务）
- 技术 lead（懂可行性）
- 1-2 个潜在用户（如果可触达）

可选：
- 设计 / UX
- 客服 / 售后（听用户声音）
```

### 第 3 步：5 维发散（15-30min）

| 维度 | 问题 |
|:--|:--|
| **用户** | 谁会用？用在哪？多久用一次？|
| **场景** | 用户当前的痛点是什么？|
| **方案** | 怎么解决？有几个方案？|
| **边界** | 哪些不做？哪些是 MVP？|
| **指标** | 怎么算成功？|

**原则**：先发散（不评判）→ 再收敛（选 1-2 个）

### 第 4 步：收敛成一句话需求（10min）

模板：

```
"[目标用户] 在 [场景] 下，想要 [动作]，从而 [价值]"
```

**示例**：
- ✅"**独立开发者** 在 **写代码时**，想要 **快速记录 TODO**，从而 **不遗漏任务**"
- ❌"做一个 TODO 工具"（缺 4 个要素）

### 第 5 步：写边界清单（10min）

```markdown
## 范围内
- 功能 A
- 功能 B

## 范围外
- 功能 X（v2.0 再做）
- 功能 Y（不做）

## 待定
- 功能 Z（待 PM 确认）
```

## ✅ 验收 Checklist

- [ ] 一句话需求含 4 要素（用户/场景/动作/价值）？
- [ ] 范围边界明确（范围内 / 外 / 待定 三类）？
- [ ] 至少 3 个角色参与？
- [ ] 输出"范围清单"文档（建议 1 页）？

## 🩸 反范式（4 类常见错误）

### 错误 1：范围太大

- **现象**："做个像淘宝的电商"
- **后果**：永远做不完
- **修复**：拆成多个 MVP，每个 MVP 一句话需求

### 错误 2：没邀请用户

- **现象**：只有 PM 和 dev 在讨论
- **后果**：做出来不是用户要的
- **修复**：必邀请至少 1 个真实用户

### 错误 3：发散不收敛

- **现象**：讨论 2 小时没结论
- **后果**：低效
- **修复**：5 维发散后必须收敛成 1 句话需求

### 错误 4：边界没写

- **现象**：模糊"都做"
- **后果**：范围漂移
- **修复**：第 5 步必写范围清单
